## 4. S1：治理内核

目标：在不引入真实 Agent 的前提下，把"谁能做什么、越界怎么办、事后怎么查"跑通。执行器是脚本化的，只负责发起动作请求。

实现状态：S1-01～S1-13 已完成，9 条出口场景由 `pnpm test` 覆盖（41 项测试通过）。设计说明见 [S1 治理内核设计](design/s1-governance.md)。

### 4.2 出口场景（必须全部通过）

1. 缺验收标准的目标只能存为草稿，并列出缺失项。
2. 计划预算合计超过目标预算时，批准被拒绝。
3. 批准计划后自动签发 Grant；未批准则没有任何授权。
4. Grant 内的 `repo.write` 放行；未授予的 `repo.merge` 直接拒绝且不生成卡片。
5. `repo.push` 到非自有分支触发升级；批准后仅当次有效，第二次仍被拦截。
6. Builder 请求 `secret.read` 属于无资格，直接拒绝。
7. 升级超过设定时长未裁决，目标转阻塞，不自动放行。
8. 取消目标后，所有 Grant 失效，后续调用全部拒绝。
9. 任一决定都能从审计还原：谁、何时、依据哪条授权、结果如何。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 授权模型抽象过度 | 固定 15 个动作，P0 只实现用到的，其余返回拒绝 |
| 存在绕过网关的写路径 | 架构测试 + 单一入口 + 代码评审清单 |

## 10. P0 完成定义

- 10 条 P0 功能需求均有对应场景并通过。
- 真实仓库完成至少一次"目标 → PR → 验证 → 验收"。
- 全程没有一次未授权动作被执行。
- 任一目标可由他人仅凭审计还原。
- 目标结束后授权全部失效，复盘记录已生成。
